# Issue completion report

Post the form on the originating Issue when the investigation stops or is handed over for review, before merge. An agent may report implementation complete and identify pending review. The researcher decides final acceptance. Link related PRs, successor Issues and dependencies. Keep outstanding objectives open or record the reason for closing them. After an abrupt interruption, the researcher records what stopped and what evidence can be recovered. Treat an absent report as an unknown outcome.

```markdown
### Completion report

- **Objective and outcome** — Complete, partial, blocked, disproved, superseded, or interrupted. For blocked work, state whether the blocker concerns mathematics, resources, or a technical dependency.
- **Provenance** — Base commit, pinned toolchain, session reference if available, and links to related PRs or a recoverable branch or patch.
- **Verified progress** — What is committed and checked, with exact commands and results. Identify local or unverified experiments.
- **Approaches and failures** — Distinct strategies, observed failures, and evidence such as an error, proof state, counterexample, or source location.
- **Outstanding work** — Obstruction, uncertainty, and the next step or dependency. Link successor Issues where available.
- **Stopping and resources** — Why work stopped, elapsed time or resource information when available, and unknowns.
- **Repository changes** — List changes and link the PR, or state explicitly “No PR” and explain why.
```
