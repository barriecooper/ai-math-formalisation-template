# GitHub walkthrough

1. **Create a project.** When the owner has enabled the GitHub template setting, choose **Use this template → Create a new repository**. You can also copy the repository files into a new repository. Check [GitHub setup](github-setup.md), then work through the [Lean starter](../lean/README.md) if you are using Lean.
2. **Commission an agent.** In **Issues → New issue**, select **Formalisation task**. Paste or link the informal theorem, state the expected hypotheses, specify which files may change, and give a stopping rule. Share the Issue URL with your chosen coding assistant and ask it to read `AGENTS.md` and `METHODOLOGY.md`, implement the bounded task, and open a PR for review. Check the assistant has repo access. For private material, follow the confidentiality guidance in the methodology.
3. **Review the PR.** Open **Files changed**, read the formal statement alongside the Issue, then inspect the proof and assumptions. Review the **Checks** tab and reproduce the commands when practical. Ask a separate reviewer to use the [review guide](review.md). Use **Review changes** to leave findings or request changes. The researcher decides when the evidence supports acceptance.
4. **Record a failed investigation.** If an agreed stopping condition is reached, post the [completion report](completion-report.md) as a comment on the Issue. Record what failed, the evidence, and what would enable a retry. For example, use `outcome: blocked` and `blocker: mathematics` when a definition requires a researcher decision. If there is no useful change to review, record “No PR” and leave the outstanding objective visible on the Issue.
